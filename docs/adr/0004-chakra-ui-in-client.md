# Adopt Chakra UI in apps/client, removing Tailwind

`apps/client` was scoped to Tailwind CSS, with Chakra UI reserved for `apps/website` only. Designing the global chat window surfaced a real need for floating, draggable, resizable windows with minimize/maximize/restore behavior — and Chakra's `FloatingPanel` (built on Ark UI) already provides all of that natively, including restoring a panel's last manually-resized size after minimizing. Rebuilding the same drag/resize/stage machinery on top of Tailwind plus a headless primitives library would mean reimplementing what Chakra already ships, for a feature set (more floating chrome: private messages, party panel, and similar) that's already on the roadmap, not a one-off.

We considered scoping Chakra to just the floating/overlay chrome and keeping Tailwind for the rest of `apps/client`, but running two styling systems side by side in one app long-term costs more in inconsistency and mental overhead than a one-time migration does. We're removing Tailwind from `apps/client` entirely instead, porting its existing Tailwind-styled screens (auth forms, character list/creation, the game-canvas wrapper) to Chakra faithfully — same behavior and appearance, no redesign — before building anything new on top of it.

`apps/client` gets its own local Chakra system configuration, not a shared one with `apps/website`: that app's `theme.ts` only customizes fonts via Next.js's `next/font` CSS variables, which don't exist outside a Next.js build. PixiJS rendering is unaffected either way — it already lives in the React tree as a sibling component, and this only changes what the surrounding React chrome is built with.
