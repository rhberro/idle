# Server-authoritative Character stats with Tibia XP curve

The Character's level, cumulative experience, health, maxHealth, mana, and maxMana live server-authoritatively in `services/game-server`'s in-memory state, loaded from `characters` on WebSocket connect and persisted back on disconnect. They're pushed to the owning client via a private `own-character-status` message and refreshed on `request-character-status` from the client (triggered on tab `visibilitychange`). The XP-to-next-level curve is Tibia's published cubic `expForNextLevel(L) = 50·(L² − 3L + 4)`, which is the closed form of CipSoft's `E(L+1) − E(L)` and identical to Canary's `getExpForLevel` evaluated via Horner form — the Tibia research pinned the values for levels 1–200 and they're baked into the `expForNextLevel` test. This expands ADR 0003's game-server scope from positions-only to positions + Character stats. We considered client-side state (would force a rewrite when combat lands) and DB-only (same problem, no in-memory value); both rejected.
